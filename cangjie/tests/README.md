# Cangjie fixtures and Python goldens

`src/tests/integration_test.cj` compares the Cangjie engine against the Python
implementation of the same six MCP tools. The comparison data lives here:

| Path | What it is |
| --- | --- |
| `fixtures/` | fifteen committed PDFs, generated by `generate_fixtures.py` |
| `goldens/` | the Python baseline for every fixture, generated by `generate_goldens.py` |
| `generate_fixtures.py` | fixture generator (reportlab + `tests/pdf_fixtures.py` + hand-written PDFs) |
| `generate_goldens.py` | golden generator (`pdf_inspector_mcp.extractor` / `export`) |

Both generators are deterministic: reportlab runs with `rl_config.invariant = 1`
(fixed document id and dates), Pillow adds no image timestamps, the hand-written
PDFs carry no `/ID`, JSON uses `indent=2` with a trailing newline, and the export
timestamp is pinned to `2026-01-01T00:00:00.000Z`. Running either script twice
produces byte-identical output.

## Regenerating (run from the repository root)

```bash
.venv/bin/python cangjie/tests/generate_fixtures.py
.venv/bin/python cangjie/tests/generate_goldens.py
```

`generate_goldens.py` also writes `goldens/errors.json`: the message fragments
the Python server produces for the unreadable fixtures and the tool-argument
errors. Each fragment is checked against the real Python tool while generating,
so the file can never claim a message the baseline does not emit. Absolute paths
are not stored (they differ per machine); the Cangjie test asserts that its own
message *contains* the fragment.

**A fixture change is only complete after both scripts ran** - the integration
test reads the committed goldens, so a stale golden fails the Cangjie suite
instead of passing silently.

## Fixtures

| Fixture | Pins down |
| --- | --- |
| `text.pdf` | one word (`alphaword`) in Helvetica 12 |
| `multipage.pdf` | three pages, distinct text and font size per page |
| `table.pdf` | 2x2 ruled grid with one empty cell (pdfplumber reports `None`) |
| `image.pdf` | one embedded PNG XObject |
| `styled.pdf` | three pages: Helvetica 10/14 stroked red/blue, Courier 12 green |
| `blank.pdf` | one page, no font resources at all |
| `zero.pdf` | empty page tree (0 pages) |
| `mediabox.pdf` | MediaBox `[0 100 612 892]`: non-zero origin, 612x792 page |
| `jpeg.pdf` | real DCTDecode JPEG payload |
| `quoted-table.pdf` | cell holding `a,"b` + newline + `c` (CSV quoting worst case) |
| `garbage.pdf` | readable file that is not a PDF |
| `encrypted.pdf` | StandardEncryption, user password `userpw` |
| `corrupt-stream.pdf` | structure readable, page content stream replaced with `0xFF` |
| `xref-stream.pdf` | hand-written xref stream + uncompressed ObjStm |
| `xref-stream-flate.pdf` | FlateDecode ObjStm + xref stream with PNG Up predictor |

## Goldens

For every readable fixture: `<name>.metadata.json`, `<name>.page1.json`,
`<name>.document.json` (`metadata`/`pageCount`/`pages`), `<name>.fonts.json`,
`<name>.export.json` and `<name>.export.csv`. `zero.pdf` has no `page1.json`
(Python raises for page 1 of a zero-page document); its document/export payloads
simply hold zero pages. `errors.json` holds the error fragments.

## Running the checks

```bash
# from cangjie/
~/.cjv/bin/cjv run lts-1.0.0 cjpm test      # unit + integration tests
bash scripts/test-all.sh                    # build + cjpm test + e2e smoke
```

`cjpm test` runs with the project directory (`cangjie/`) as its working
directory, which is why the tests reference `tests/fixtures/...` and
`tests/goldens/...` relatively.

## Known deviations (asserted explicitly, not papered over)

* `rect.fill`: the Python extractor derives it from
  `non_stroking_color is not None` (true for a stroke-only rectangle), the
  Cangjie engine from the painting operator (`S` -> false). The integration test
  pins the Cangjie value in `rectFillFollowsThePaintingOperator` and skips the
  field in the generic comparison.
* Word order when the content stream draws lines out of reading order:
  `quoted-table.pdf` emits `plain` before `c`. pdfplumber groups words in
  content-stream order, the Cangjie splitter in descending-baseline order, so
  the CSV comparison for that fixture skips the `# words` text column while
  still comparing characters and table cells exactly.
